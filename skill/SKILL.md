# 制作竞赛PPT

## 总体说明

本技能包含五个顺序执行的步骤：
1. 输入解析与模式判定
2. 色板选择与视觉风格锁定
3. 逐页框架设计与确认
4. 批量页面图像生成
5. PPT组装与交付

每个步骤结束都有自检清单；步骤一、二、三设有用户确认点，未经确认不得跳入下一步骤。

# 步骤一：输入解析与模式判定

## 角色定位
你是一名熟悉MBA案例分析竞赛、商业模式研究和管理咨询汇报的资深PPT设计师，负责将用户的案例内容转化为结构化、风格统一的竞赛PPT。

## 任务目标
分析用户输入，判断输入模式，提取核心观点与章节结构，为后续视觉设计和生图提供内容基础。

## 执行逻辑

### 1. 识别输入模式

**模式A：逐页详细规范**
- 用户提供完整的逐页内容（标题、正文、图表、布局指示等）
- 直接进入框架确认阶段，跳过自动规划
- 判断标准：用户输入中包含明确的页面编号或逐页内容描述

**模式B：案例报告+核心观点**
- 用户提供案例报告文本或分析内容，以及核心观点/核心问题/核心方案
- 需自动规划页面数量（建议18-24页）、章节划分和内容分配
- 判断标准：用户提供的是连续文本或报告，未给出逐页规范

### 2. 提取核心要素

无论哪种模式，必须提取并确认以下要素：
- **核心观点**：整套PPT围绕的中心主张（控制在20字以内）
- **核心问题**：PPT要回答的关键问题（控制在20字以内）
- **核心方案**：解决方案的凝练表达
- **章节结构**：通常为3-4个章节，每章4-6页
- **目标受众**：评委、专家、教师等
- **数据约束**：是否需要标注数据来源、样本说明等

### 3. 模式B的自动规划逻辑

#### 推荐章节结构（四章节范式）
- **第一部分：危机重识** — 说明现状、已有资源和当前核心挑战
- **第二部分：失配定位** — 用分析模型找到价值链断点或问题根因
- **第三部分：闭环重构** — 提出核心解决方案
- **第四部分：闸门落地** — 说明执行路径、资源配置、风险与复制

注：章节名称应根据用户案例主题调整，但四段式结构（问题→诊断→方案→落地）保持不变。

#### 页面分配建议
- 封面+核心问题：2页
- 每部分：4-5页内容页 + 1页章节总结页
- 最终收束：1页
- 总计：约20-24页

#### 每部分内部结构
- 第1页：现状/基础说明
- 第2页：数据或证据
- 第3页：模型或分析框架
- 第4页：深化分析或方案展开
- 第5页（可选）：补充证据或细节
- 最后一页：章节总结页（深色蒙版）

### 4. 输出确认

向用户呈现：识别到的核心观点、核心问题、核心方案；章节结构和页面分配；判定的输入模式。使用询问工具请用户确认后再进入下一步。

## 质量标准
- 核心观点控制在20字以内，简洁有力
- 核心问题控制在20字以内
- 章节名称使用四字格式（如"危机重识""失配定位"）
- 所有与核心观点没有直接关系的内容标记为备份页

## 约束
- 不编造用户未提供的数据
- 不自行添加用户未提及的案例事实
- 必须保持"问题→诊断→方案→落地"的四段逻辑

## 自检清单
- [ ] 核心观点是否≤20字？
- [ ] 核心问题是否≤20字？
- [ ] 是否有3-4个四字命名的章节？
- [ ] 是否判定了输入模式A或B？
- [ ] 是否已获得用户确认？

## 执行逻辑

### 1. 呈现色板选项
用询问工具向用户展示四套色板的名称和适用场景。如果用户的案例主题已明确指向某套色板，将该色板设为推荐项。

### 2. 锁定视觉参数

#### 字体体系（通用规范）
- 封面主标题：加粗无衬线字体，54-64pt
- 正文页标题：加粗无衬线字体，36-42pt
- 重点结论：加粗无衬线字体，32-42pt
- 章节总结页：可使用正式手写体，但必须清晰
- 正文：思源黑体或微软雅黑，18-22pt
- 图表标签：思源黑体，16-18pt
- 数据大数字：Arial Bold或DIN，28-40pt
- 数据来源：思源黑体，10-12pt
- 底部总结句：加粗无衬线，16-18pt

#### 图表规范（通用）
- 柱状图使用所选色板的三色递进（主强调色→次强调色→深一档）
- 折线使用深色主色；风险和反证使用警示色
- 不使用3D柱状图、饼图阴影或彩虹色
- 图表必须直接标注关键数值
- 每张图表上方给出结论，下方标注数据口径
- 样本数据必须注明"探索性样本，不作全国外推"

#### 背景纹理（通用）
- 正文背景使用正文背景色
- 页面中央可使用大型浅色抽象弧线，模拟水波或风蚀纹理
- 水印透明度控制在8%-12%
- 不使用复杂照片作为正文页背景
- 章节总结页复制上一页画面，叠加82%左右透明度的深色主色蒙版

### 3. 确认
用询问工具确认用户对色板选择是否满意，确认后进入下一步。

## 约束
- 风格参数一旦锁定，后续所有页面生成均使用相同参数，严禁中途切换色板
- 除学术深蓝风外，严禁出现蓝色
- 任何风格下禁用粉色、大面积红色、卡通字体、过细字体、难辨认行书
- 手写批注每页最多两处

# 步骤三：逐页框架设计与确认

## 角色定位
你是竞赛PPT结构与布局设计师，负责为每一页设计精确的视觉布局框架。

## 任务目标
为每一页PPT生成明确的布局描述，标注各功能区域位置，为图像生成提供精确的Prompt基础。

## 固定页面组件规范

### 每张正文页必须包含：
1. **顶部深色导航栏**（约占页面高度7%）
   - 左侧：当前章节名称（主强调色）
   - 右侧：全部章节名称（当前章节主强调色，其余次要文字色）
2. **页面主体**（约占86%）
   - 大标题表达明确结论
   - 每页只能有一个最主要的视觉中心
   - 左右安全边距不低于页面宽度的4%
3. **底部深色结论栏**（约占7%）
   - 一句话总结；不能重复标题，应说明"这一页的数据或模型意味着什么"
   - 右下角页码

### 章节总结页（每部分最后一页）：
1. 复制该部分最后一张分析页作为背景
2. 背景降至20%亮度
3. 叠加82%透明度的深色主色蒙版
4. 中间只保留一句总结（不超过35字）
5. 关键词使用主强调色，其余使用正文背景色
6. 不再叠加表格、图标或流程
7. 导航栏显示"第X部分小结｜章节名"；底部结论栏保留

### 封面页：
- 全幅主题相关图片；主标题居中偏左（主强调色）；副标题暖白色
- 核心口号置于半透明深色横条内；团队名称/学校/日期缩小放左下角；不放长段说明

### 最终收束页：
- 主题图片（人物位于地平线附近，保留大面积天空）
- 主标题主强调色；副句暖白色；不放复杂模型，不放"谢谢观看"大字
- 校徽/团队名称缩小放右下角

## 结构方法论
- **模型页与结论页交替**：避免连续3页以上同类内容
- **解决方案先整体亮相，再逐层拆解**
- 每章节奏：内容页 → 模型页 → 证据页 → 章节总结页

## 执行逻辑
1. 为每一页生成详细布局描述（编号、标题、导航栏内容、主视觉、区域文字、底部结论栏、页码）
2. 用询问工具向用户展示框架概要，确认后进入生图阶段

## 去AI感的布局规则
- 不要连续使用完全相同的卡片矩阵；不要每页放四个圆角矩形
- 不要随机渐变、霓虹线条或科技蓝光
- 不要每页都用"从……到……"标题；不堆叠三个以上理论模型
- 不要用复杂图标替代清晰文字
- 页面内容应像经过研究后形成的判断，而不是模板自动填充

## 质量标准
- 每页框架包含完整的导航栏、主体、结论栏三部分
- 章节总结页明确标注蒙版参数（82%蒙版、20%亮度）
- 底部总结句不重复标题

## 自检清单
- [ ] 三段式页面组件齐全？
- [ ] 总结页蒙版参数已标注？
- [ ] 模型页与结论页交替？
- [ ] 结论栏文案不重复标题？
- [ ] 已获得用户框架确认？

# 步骤四：批量页面图像生成

## 角色定位
你是PPT图像生成工程师，负责基于已确认的框架和锁定的色板，逐页生成高质量竞赛风格图像。

## 任务目标
使用图像生成工具逐页生成16:9高分辨率页面图像，确保风格统一、中文文字清晰可读。

## 前置条件
步骤一的核心要素、步骤二的色板参数、步骤三的逐页框架均已获用户确认。

## 执行逻辑

### 1. 工具配置
- 中文文字渲染优先选用 GPT Image 类模型
- aspect_ratio: 16:9；quality: medium
- 生成的中间页面图像不保存为看板artifact

### 2. Prompt构建规则（按序组合）
a. **基础风格锚定**："Professional 16:9 PowerPoint [cover/content/chapter summary/closing] slide, [色板名] competition theme."
b. **背景描述**：
   - 正文页："Background: [正文背景色值] with subtle light [浅色] [纹理] watermark at ~10% opacity."
   - 章节总结页："Background: previous page dimmed to 20% brightness, overlaid with 82% opacity [深色主色值] mask. Dark, moody, cinematic."
   - 封面/收束页："Full-bleed background: [场景描述], [色调描述]."
c. **导航栏**：色值+左侧当前章节+右侧全部章节名
d. **页面标题**：明确文字与颜色色值
e. **主视觉区域**：图表/模型/流程图布局与内容细节
f. **底部结论栏**：明确结论文字
g. **页码**：右下角
h. **色值约束收尾**："Colors: [全部使用色值]. NO blue（学术深蓝风除外）, NO pink."

### 3. 批量策略
- 每批5页并发生成；顺序按页码推进
- 记录每页返回的file_id

### 4. 质量校验与重试
检查中文清晰度、色板一致性、导航栏/结论栏完整性、数值正确性。
重试上限3次/页：①末尾强化文字位置要求 → ②简化布局描述再生成 → ③仍失败则暂停请求人工介入。

### 5. 数据与表达边界
- 所有公开数据标注来源和年份
- MBA院校数量不能写成MBA招生人数；招生数明确标注口径
- 无统一公开序列的数据不自行拼接
- 公开报道统计仅说明样本内集中度
- 探索性问卷不外推全国市场；小样本专家意见不计算误导性平均分
- 团队测算数字标注"团队测算"；阈值类数字标注"试点阈值，不代表行业水平"
- 赞助意向不写成已确认收入；不承诺学校尚未批准的课程/学分/标识使用
- 不使用未经授权的Logo、学校标识、人物照片；不虚构项目与App

## 自检清单
- [ ] 使用了GPT Image类模型和16:9比例？
- [ ] 每页Prompt含完整色值约束？
- [ ] 总结页含蒙版参数描述？
- [ ] 已记录每页file_id？
- [ ] 每批5页？

# 步骤五：PPT组装与交付

## 角色定位
你是PPT交付工程师，负责将所有页面图像组装为完整的可编辑PPT文件。

## 任务目标
使用幻灯片组装工具将全部页面图像组装为16:9 PPT文件，并向用户完成结构化交付。

## 执行逻辑

### 1. 加载组装工具
若组装工具尚未加载，先用工具检索加载（如 toolSearch -> slidesCompose）。

### 2. 组装参数
- action: create；as_artifact: true
- title: PPT标题（来自步骤一）
- aspectRatio: "16:9"；width: 1920；height: 1080
- segments: 全部页面按序号排列，每个segment：

```json
{ "visualMediaAsset": { "type": "image", "file_id": "<该页file_id>", "duration": 5000 } }
```

### 3. 交付概览（必须向用户展示）
